# Contratos de CLI

As versões e os formatos verificados estão em [fixtures/cli-protocol-versions.json](fixtures/cli-protocol-versions.json). São registros sanitizados: não contêm prompts de projetos, credenciais nem caminhos pessoais.

- `npm test`: contratos, retomada, erros, concorrência, permissões, arquivos incrementais, UTF-8, restrições de leitura e snapshots finais.
- `npm run test:desktop`: Electron real com CLIs offline. Nos três provedores verifica texto parcial no chat e saída intermediária no shell enquanto o turno ainda está ativo; aprova e nega ações pela interface; confere retomada após reiniciar.
- `npm run test:cli-live`: diagnóstico **opcional com as CLIs reais e suas autenticações locais**. Executa um comando Node inofensivo que imprime por quatro segundos, em pasta temporária, e retoma cada conversa. Pode consumir cota. Para uma CLI: `npm run test:cli-live -- --providers=claude` (também aceita `codex` e `antigravity`). Não integra o teste offline nem o CI padrão.

Diagnóstico nativo nesta implementação: Claude mostrou bytes do arquivo `.output` antes do `tool_result`; AGY mostrou saída intermediária de tarefa antes do resultado final; Codex mostrou deltas de texto e de comando antes de `turn/completed`. Na versão Codex 0.166.0, o primeiro buffer de um comando pode aparecer somente no snapshot final; o adaptador preserva esse trecho e mostra os deltas seguintes imediatamente. Logs e indicadores de atividade não inventam texto ou progresso do modelo.

Regressão Claude 2.1.316: o modelo escolheu `npm test 2>&1 | tail -60`, que retém a saída até o encerramento. O contexto adicional do launcher orienta execução direta de testes, builds e instalações, respeitando pedidos explícitos de filtragem. Não altera comandos autorizados nem permissões. Para testar a escolha de comando pelo modelo, `npm run test:cli-live -- --providers=claude --npm-test` cria um projeto npm temporário com saída por oito segundos e usa um pedido comum de testes, sem ditar o comando completo. Verifica saída intermediária e continuidade da conversa. Programas que internamente retêm stdout ainda podem exigir configuração própria para emitir progresso.

Aprovações nativas de Claude (`stdio`) e AGY (hook com canal autenticado) foram exercitadas com uma gravação inofensiva em diretório temporário. O teste de interface dos três protocolos cobre os botões Autorizar uma vez e Negar. Os testes de contrato verificam cancelamento, ids de uso único e isolamento de conversa. Uma solicitação que exige campos adicionais de entrada não deve ser tratada como uma autorização genérica.

Interrupção: nos três provedores, o teste integrado cria uma execução que não termina sozinha, envia duas mensagens à fila, aciona Parar e verifica que elas nunca chegam à CLI. Confere texto parcial salvo, retomada com o mesmo ID e interrupção digitando `para`. Testes unitários cobrem envios que chegam atrasados depois de Parar e isolamento entre conversas; um teste com processos Node reais verifica que o comando filho para enquanto outro grupo de processos continua ativo.

Mensagem durante a execução (diagnóstico com as CLIs reais, 2026-11-01): Claude Code 2.1.316 aceita uma linha `user` no stdin com o turno em andamento, lê a mensagem na próxima etapa e devolve **um único** `result` para as duas. O Codex 0.166.0 oferece `turn/steer` (`threadId`, `expectedTurnId`, `input`) no app-server; o contrato é coberto por teste simulado e a recusa (turno já encerrado) devolve a mensagem à fila. O Antigravity 1.4.12 **não** injeta: uma linha `user` no stdin durante o turno fica enfileirada pela própria CLI e roda como um segundo turno, com `result` próprio, depois do primeiro. Por isso, no AGY a mensagem espera na fila do app e "Enviar agora" interrompe a execução atual. O `turn/steer` do Codex real ainda não foi exercitado com a CLI.

Comando em segundo plano (diagnóstico com as CLIs reais, 2026-11-01): no Claude Code 2.1.316 o `tool_result` de um Bash com `run_in_background` volta na hora e o turno termina, enquanto a IA aguarda o `task_notification`; por isso o app mantém o comando como "rodando" até o aviso. No Codex 0.166.0 um processo desvinculado (`nohup … &`) termina como comando concluído dentro do turno e a CLI não avisa o fim depois: não há estado "aguardando aviso". No Antigravity 1.4.12 o passo `run_command` fica `ACTIVE` até o comando acabar (45 s no teste) e o `result` só chega depois; o turno não termina antes do comando.

Validade do cache de prompt (diagnóstico com as CLIs reais, 2026-11-01, em registros de sessões locais): o Claude Code 2.1.316 separa a escrita do cache por validade em `usage.cache_creation` (`ephemeral_1h_input_tokens` / `ephemeral_5m_input_tokens`; nas sessões verificadas, só 1 h); o app usa isso para a contagem regressiva, renovada a cada chamada. O Codex 0.166.0 informa só o cache lido (`cachedInputTokens`) e envia `prompt_cache_key`, sem validade definida pelo cliente. O Antigravity 1.4.12 informa `cache_read_tokens` por etapa `agent_response`, também sem validade. Nesses dois o indicador mostra só o tempo desde a última chamada. A contagem regressiva é coberta por teste simulado com valores reais; não houve espera real até a expiração.

Troca de modelo: o aviso parte da regra documentada pelos provedores de que o cache de prompt é separado por modelo; não foi medido com as CLIs reais. O modelo registrado é o escolhido no app (antes de resolver aliases), coberto por testes simulados nos três protocolos. Troca só do nível de raciocínio não gera aviso: o efeito no cache não foi verificado.

Troca de permissão durante a execução (diagnóstico com a CLI real, 2026-11-01): o Claude Code 2.1.316 aceita no stdin (`-p --input-format stream-json --permission-prompts host --permission-prompt-tool stdio`) o `control_request` `{"subtype":"set_permission_mode","mode":"plan|acceptEdits|bypassPermissions|default"}`. Ele responde `control_response` `success` e emite `system`/`status` com o novo `permissionMode`; não precisa de `initialize` antes. `bypassPermissions` só é aceito se o processo partiu com `--allow-dangerously-skip-permissions` (ou `--dangerously-skip-permissions`); sem isso responde `error` `bypass_not_launched`. Por isso o app passa a primeira flag, que só habilita o modo e não o liga. Esse diagnóstico não chamou o modelo: não foi verificado com uma ferramenta de verdade se uma aprovação já pendente é reavaliada; o app a libera ele mesmo ao passar para "Acesso total". "Global da CLI" não tem modo equivalente, então voltar a ele reinicia a CLI na próxima mensagem. No AGY 1.4.12 o modo, as regras de negação e o sandbox são fixados na partida (`--mode`/`--settings`); ao vivo só muda a decisão da ponte do hook `PreToolUse`, ou seja, para uma conversa que partiu em "Aceitar edições" (para somente leitura a ponte nega o que não é leitura). O restante vale ao reiniciar na próxima mensagem. O app-server do Codex 0.166.0 recebe `approvalPolicy`/`sandbox` em `thread/start`/`thread/resume`, então a troca vale na próxima mensagem. Coberto por testes de contrato simulados (runner, ponte AGY, broker) e pelo smoke do app nos três provedores; o comportamento real do AGY com o hook após a troca não foi medido.

Ditado por voz (diagnóstico real, 2026-11-02, i5-13420H sem GPU dedicada): o motor local é o `parakeet-cli` do whisper.cpp 1.9.5 compilado com `npm run build:speech` (`GGML_NATIVE`, AVX2/FMA/VNNI) e o modelo `ggml-parakeet-tdt-0.6b-v3-q8_0`. Na linha de comando, 6 s de fala em português levaram 0,9 s e 20 s levaram 4,7 s, com pontuação e ~800 MB de pico de memória. O Whisper large-v3-turbo levou 35–38 s pelos mesmos áudios (o encoder processa sempre a janela de 30 s), e o binário pré-compilado do pacote npm `@fugood/node-whisper-linux-x64` saiu sem instruções AVX e ficou mais de 5 min sem terminar; por isso foram descartados. No Electron, com o microfone falso tocando fala real (`BEAGLEDOCK_SMOKE_SPEECH_AUDIO=<wav> BEAGLEDOCK_SMOKE_SPEECH_MODELS=~/.beagledock/models BEAGLEDOCK_SMOKE_SPEECH_EXPECT=Senna npm run test:desktop`), 8 s de fala viraram texto 2,4 s depois de concluir a gravação, contando conversão, IPC, partida do motor e carga do modelo. Sem essas variáveis, o smoke usa o tom do microfone falso do Chromium, confere a oferta de download quando falta o modelo e exercita o fluxo da API contra um servidor local, verificando o estado "Transcrevendo…" antes do texto. A web Speech API do Chromium não funciona no Electron 45 (`network`; modo local `unavailable`). Das CLIs, só o Antigravity transcreveu áudio (Gemini, 13,5 s para 2,6 s de fala); o Claude Code 2.1.316 não ouve áudio e o Codex 0.166.0 não pôde ser verificado (cota esgotada).
