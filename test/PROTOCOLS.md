# CLI contracts

The verified versions and formats are in [fixtures/cli-protocol-versions.json](fixtures/cli-protocol-versions.json). They are sanitized records: they contain no project prompts, credentials or personal paths.

- `npm test`: contracts, resuming, errors, concurrency, permissions, incremental files, UTF-8, read restrictions, final snapshots and the parity of the interface languages.
- `npm run test:desktop`: real Electron with offline CLIs. For the three providers it checks partial text in the chat and intermediate output in the shell while the turn is still active; approves and denies actions through the interface; checks resuming after a restart.
- `npm run test:cli-live`: **optional diagnosis with the real CLIs and their local authentication**. Runs a harmless Node command that prints for four seconds, in a temporary folder, and resumes each conversation. It may use quota. For one CLI: `npm run test:cli-live -- --providers=claude` (also accepts `codex` and `antigravity`). It isn't part of the offline test or the standard CI.

Native diagnosis in this implementation: Claude showed bytes of the `.output` file before the `tool_result`; AGY showed a task's intermediate output before the final result; Codex showed text and command deltas before `turn/completed`. In Codex 0.166.0, a command's first buffer may only appear in the final snapshot; the adapter keeps that chunk and shows the following deltas immediately. Logs and activity indicators don't make up model text or progress.

Claude 2.1.316 regression: the model chose `npm test 2>&1 | tail -60`, which holds the output until the end. The launcher's additional context steers tests, builds and installs to run directly, respecting explicit requests for filtering. It doesn't change authorized commands or permissions. To test the model's choice of command, `npm run test:cli-live -- --providers=claude --npm-test` creates a temporary npm project with eight seconds of output and uses an ordinary request to run the tests, without dictating the full command. It checks intermediate output and the conversation's continuity. Programs that hold stdout internally may still need their own configuration to emit progress.

Native approvals of Claude (`stdio`) and AGY (hook with an authenticated channel) were exercised with a harmless write in a temporary directory. The interface test of the three protocols covers the Allow once and Deny buttons. The contract tests check cancellation, single-use ids and conversation isolation. A request that needs additional input fields must not be treated as a generic authorization.

Interruption: for the three providers, the integrated test creates a run that doesn't end on its own, sends two messages to the queue, triggers Stop and checks that they never reach the CLI. It checks the saved partial text, resuming with the same ID and interrupting by typing `para`. Unit tests cover sends that arrive late after Stop and isolation between conversations; a test with real Node processes checks that the child command stops while another process group stays active.

Message during the run (diagnosis with the real CLIs, 2026-11-01): Claude Code 2.1.316 accepts a `user` line on stdin with the turn in progress, reads the message at the next step and returns **a single** `result` for both. Codex 0.166.0 offers `turn/steer` (`threadId`, `expectedTurnId`, `input`) in the app-server; the contract is covered by a simulated test and a refusal (turn already over) puts the message back in the queue. Antigravity 1.4.12 does **not** inject: a `user` line on stdin during the turn is queued by the CLI itself and runs as a second turn, with its own `result`, after the first. That's why in AGY the message waits in the app's queue and "Send now" interrupts the current run. Real Codex `turn/steer` hasn't been exercised with the CLI yet.

Background command (diagnosis with the real CLIs, 2026-11-01): in Claude Code 2.1.316 the `tool_result` of a Bash with `run_in_background` comes back right away and the turn ends, while the AI waits for the `task_notification`; that's why the app keeps the command as "running" until the notice. In Codex 0.166.0 a detached process (`nohup … &`) ends as a finished command inside the turn and the CLI doesn't report the end later: there's no "waiting for notice" state. In Antigravity 1.4.12 the `run_command` step stays `ACTIVE` until the command finishes (45 s in the test) and the `result` only arrives afterwards; the turn doesn't end before the command.

Prompt cache lifetime (diagnosis with the real CLIs, 2026-11-01, on local session records): Claude Code 2.1.316 splits the cache write by lifetime in `usage.cache_creation` (`ephemeral_1h_input_tokens` / `ephemeral_5m_input_tokens`; in the sessions checked, only 1 h); the app uses it for the countdown, renewed on every call. Codex 0.166.0 reports only the cache read (`cachedInputTokens`) and sends `prompt_cache_key`, without a client-defined lifetime. Antigravity 1.4.12 reports `cache_read_tokens` per `agent_response` step, also without a lifetime. For those two the indicator shows only the time since the last call. The countdown is covered by a simulated test with real values; there was no real wait until expiration.

Model switch: the notice is based on the providers' documented rule that the prompt cache is per model; it wasn't measured with the real CLIs. The recorded model is the one chosen in the app (before resolving aliases), covered by simulated tests in the three protocols. Changing only the reasoning level doesn't produce a notice: its effect on the cache wasn't verified.

Permission change during the run (diagnosis with the real CLI, 2026-11-01): Claude Code 2.1.316 accepts on stdin (`-p --input-format stream-json --permission-prompts host --permission-prompt-tool stdio`) the `control_request` `{"subtype":"set_permission_mode","mode":"plan|acceptEdits|bypassPermissions|default"}`. It answers a `success` `control_response` and emits `system`/`status` with the new `permissionMode`; it doesn't need `initialize` first. `bypassPermissions` is only accepted if the process started with `--allow-dangerously-skip-permissions` (or `--dangerously-skip-permissions`); without it, it answers `error` `bypass_not_launched`. That's why the app passes the first flag, which only enables the mode and doesn't turn it on. This diagnosis didn't call the model: it wasn't verified with a real tool whether an already pending approval is reevaluated; the app releases it itself when switching to "Full access". "CLI global" has no equivalent mode, so going back to it restarts the CLI on the next message. In AGY 1.4.12 the mode, the deny rules and the sandbox are fixed at startup (`--mode`/`--settings`); live, only the decision of the `PreToolUse` hook bridge changes, that is, for a conversation that started in "Accept edits" (for read-only the bridge denies what isn't a read). The rest applies when restarting on the next message. The Codex 0.166.0 app-server receives `approvalPolicy`/`sandbox` in `thread/start`/`thread/resume`, so the change applies on the next message. Covered by simulated contract tests (runner, AGY bridge, broker) and by the app smoke test for the three providers; the real AGY behavior with the hook after the change wasn't measured.

Voice dictation (real diagnosis, 2026-11-02, i5-13420H without a dedicated GPU): the local engine is whisper.cpp 1.9.5's `parakeet-cli` built with `npm run build:speech` (`GGML_NATIVE`, AVX2/FMA/VNNI) and the `ggml-parakeet-tdt-0.6b-v3-q8_0` model. On the command line, 6 s of Portuguese speech took 0.9 s and 20 s took 4.7 s, with punctuation and ~800 MB of peak memory. Whisper large-v3-turbo took 35–38 s for the same audio (the encoder always processes the 30 s window), and the prebuilt binary of the `@fugood/node-whisper-linux-x64` npm package came without AVX instructions and ran for more than 5 min without finishing; so both were dropped. In Electron, with the fake microphone playing real speech (`BEAGLEDOCK_SMOKE_SPEECH_AUDIO=<wav> BEAGLEDOCK_SMOKE_SPEECH_MODELS=~/.beagledock/models BEAGLEDOCK_SMOKE_SPEECH_EXPECT=Senna npm run test:desktop`), 8 s of speech became text 2.4 s after the recording finished, counting conversion, IPC, engine startup and model loading. Without those variables, the smoke test uses the tone of Chromium's fake microphone, checks the download offer when the model is missing and exercises the API flow against a local server, checking the "Transcribing…" state before the text. Chromium's web Speech API doesn't work in Electron 45 (`network`; local mode `unavailable`). Of the CLIs, only Antigravity transcribed audio (Gemini, 13.5 s for 2.6 s of speech); Claude Code 2.1.316 doesn't hear audio and Codex 0.166.0 couldn't be verified (quota used up).
